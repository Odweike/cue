# Архитектура macOS-видеоплеера с локальным распознаванием субтитров
### v2 — полностью с нуля, минимум/ноль сторонних библиотек

## 0. Что изменилось в этой версии

Решено: приложение пишется **полностью с нуля**, без форка чужих проектов. Дополнительно закрываем вопрос «ничего чужого»: подсистема распознавания речи теперь строится на **нативном Apple `Speech.framework` (`SpeechAnalyzer`/`SpeechTranscriber`, macOS 26+)** вместо whisper.cpp — это системный фреймворк Apple, а не сторонняя библиотека, поэтому не тянет за собой ни лицензионных файлов, ни скачивания сторонних моделей.

Независимые тесты показывают, что новый движок Apple превосходит по точности и на чистой, и на шумной речи ранее протестированные версии Whisper (включая Whisper Small), а на реальном видео транскрибирует значительно быстрее, чем Whisper large-v3. Список поддерживаемых языков (включая русский) пока меньше, чем у Whisper (~17-20 против ~100), и растёт со временем; сам API асинхронный/потоковый — хорошо подходит для «субтитров по мере просмотра».

**Открытый вопрос по движку воспроизведения остался** — см. раздел 9.

## 1. Технологический стек

| Слой | Технология | Почему |
|---|---|---|
| Движок воспроизведения | **см. раздел 9 — нужно выбрать** | AVFoundation (0 зависимостей, ограниченные форматы) vs libmpv (все форматы, минимальная лицензионная пометка) |
| UI | Swift + AppKit (borderless floating-панели) + SwiftUI внутри панелей | Нужен точный контроль над окнами/drag/рендер-слоем |
| Распознавание речи | **`Speech.framework`: `SpeechAnalyzer` + `SpeechTranscriber`** (системный API, macOS 26+) | Полностью on-device, без сторонних либ, без ручного управления моделями — система сама выделяет и подгружает нужный языковой ассет |
| Резервный движок (опционально) | whisper.cpp — **только если понадобится язык, которого нет в `SpeechTranscriber.supportedLocales`** | Не включать в MVP; держать как опциональный плагин на будущее |
| Хранение настроек | `UserDefaults` / plist / JSON-профили стилей | Нативно, без зависимостей |

```
│                        UI Layer                         │

└───────┬───────────────────────────────────┬───────────────┘
        │                                   │
┌───────▼─────────┐                ┌────────▼──────────────┐
│  PlaybackEngine   │                │  TranscriptionEngine   │
│ (AVFoundation или  │                │  (Speech.framework:     │
│  libmpv — раздел 9)│                │  SpeechAnalyzer/        │
│                   │                │  SpeechTranscriber)     │
└──────────────────┘                └────────┬───────────────┘

                                     │   SubtitleOverlayRenderer │
                                     └────────────────────────┘
```

Важное упрощение по сравнению с первой версией: `Speech.framework` — системный сервис, работающий в собственном процессе Apple под капотом (аналогично тому, как работает Siri/Dictation), поэтому **не нужен отдельный helper-процесс/XPC для изоляции** — Apple уже это сделала за вас. Вызовы просто идут асинхронно (`async/await` + `AsyncSequence`), достаточно не блокировать ими главный поток UI.

## 4. Подсистема распознавания речи (Speech.framework)

### 4.1 Два режима, как и раньше

**«Распознать» (batch/offline)**
1. `AudioExtractor` через `AVAssetReader` вытаскивает аудиодорожку видео в PCM-буфер.
2. `BatchTranscriber` прогоняет её через `SpeechTranscriber` с выбранной локалью.
3. Готовый транскрипт с таймкодами сохраняется как `.srt` рядом с видео и сразу подключается как активный трек.

**«По мере просмотра» (pipelined/live)**
1. Используется потоковый API `SpeechAnalyzer` (`AsyncSequence`) — он спроектирован именно под живую подачу аудио, поэтому можно кормить его буферами по мере воспроизведения (с небольшим опережением текущей позиции, как и в первой версии архитектуры, чтобы субтитр появлялся до того, как его нужно показать).
2. Готовые сегменты добавляются в `SubtitleModel` по мере готовности.
3. При перемотке — сбрасываем/перезапускаем поток анализа с новой позиции.

### 4.2 Проверка поддержки языка

Перед стартом любой транскрипции — проверка через `SpeechTranscriber.supportedLocales` / `isAvailable`. Если языка нет в списке:
- показываем пользователю понятное сообщение («этот язык пока не поддерживается системным распознаванием на этом Mac»);
- MVP: просто отключаем кнопку «Распознать» для неподдерживаемых языков;
- на будущее: точка расширения для опционального fallback-движка (например, whisper.cpp), но не реализовывать в первой версии.

Если для локали требуется первичная загрузка языкового ассета — показать нативный прогресс/индикатор (сравнимо с тем, как раньше планировалось скачивание Whisper-моделей, только теперь этим управляет ОС, а не ваш код).

### 4.3 Важные технические оговорки для агента
- API привязан к **macOS 26+** — установить как минимальную версию деплоймента.
- API довольно новый — закладывайте защитную обработку ошибок (например, известны кейсы «Cannot use modules with unallocated locales» при неаккуратном сравнении `Locale`) — использовать `SpeechTranscriber.supportedLocale(equivalentTo:)` для нормализации локали, а не сравнивать `Locale` напрямую.
- Не тестируется корректно в Simulator — тестировать на реальном железе.

## 5. Рендеринг субтитров — без изменений

Как и в первой версии: не полагаемся на встроенный рендер субтитров плеера (если используете libmpv — его libass; если AVFoundation — его `AVSubtitle`). Весь текст (импортированный и сгенерированный) парсится в единую модель `SubtitleModel` и рендерится собственным overlay-слоем (SwiftUI/Core Text) поверх видео — это даёт свободную кастомизацию шрифта/позиции и **два независимо стилизованных трека одновременно**.

## 6. UI-спецификация — без изменений

См. скриншоты: плавающая перетаскиваемая панель управления (borderless `NSPanel`) + выезжающая справа панель настроек с табами Видео/Аудио/**Субтитры**. Вкладка «Субтитры» теперь проще на бэкенде (не нужно показывать список моделей для скачивания — только выбор языка и, если нужно, индикатор первой загрузки языкового пакета системой), но UI-требования те же: выбор языка, кнопка «Распознать», переключатель «по мере просмотра», редактор стиля текста, отдельный редактор для второго трека.

## 7. Мультиплатформенность — обновление

С учётом привязки к `Speech.framework` (только Apple-платформы), мультиплатформенность становится ещё более гипотетической на будущее. Если когда-нибудь понадобится Windows/Linux — распознавание речи там придётся делать через что-то другое (например, тот самый whisper.cpp), поэтому `TranscriptionEngine` стоит спроектировать как **протокол** (`TranscriptionEngine: AnyObject { func transcribe(...) }`), с текущей единственной реализацией на `Speech.framework` — так при необходимости замена/добавление движка не потребует переписывать вышестоящий код.

## 8. Поэтапный план для агента

1. **Playback-движок.** Реализовать выбранный вариант (раздел 9), базовое окно, минимальный play/pause/seek.
2. **Floating control bar** по скрину 1, drag, сохранение позиции.
3. **Settings panel**: вкладки Видео/Аудио 1:1 по скрину 2.
4. **Субтитры (импорт + рендер).** Парсер `.srt/.ass/.vtt`, единая модель, overlay-рендерер, стиль, второй трек — на готовых файлах, без распознавания речи.
5. **Редактор стиля субтитров** на вкладке «Субтитры».
6. **`TranscriptionEngine` на `Speech.framework`.** Проверка поддержки локали, батч-транскрипция по кнопке «Распознать», сохранение `.srt`.
7. **Pipelined-транскрипция «по мере просмотра».** Потоковая подача аудио, обработка перемотки.
8. **Полировка.** Профили стилей, экспорт, drag&drop видео в окно.

(Модуль скачивания/управления моделями Whisper из плана исключён — больше не нужен в MVP.)

## 9. Движок воспроизведения — решено: libmpv, LGPL-сборка

Выбор: **libmpv**, собранная в LGPL-режиме — mpv с флагом `-Dgpl=false` + FFmpeg без `--enable-gpl`/`--enable-nonfree`. Даёт:
- Полную поддержку форматов/контейнеров (MKV, AVI и т.д.) — без потерь, т.к. отваливаются в LGPL-режиме только GPL-only энкодеры (x264/x265), которые плееру не нужны (он не кодирует, только декодирует).
- Единственное юридическое обязательство: включить в приложение (например, экран «Лицензии»/«О программе») текст LGPL-лицензии и копирайты mpv/ffmpeg/libass и связанных LGPL/MIT/BSD-компонентов. Исходники самого приложения при этом можно публиковать под любой лицензией (или без неё) — LGPL не «заражает» код, который её просто использует через API.
- Совместимость с распространением через GitHub и App Store (в отличие от полного GPL, LGPL прямо разрешает линковку в закрытое/ограниченное распространение — именно поэтому она и была придумана).

Собирать mpv+ffmpeg рекомендуется через готовые/документированные скрипты сборки LGPL-варианта под macOS (universal dylib, arm64+x86_64), аналогично тому, как это делает сборочный пайплайн IINA (`other/download_libs.sh`), но с явными LGPL-only флагами.
